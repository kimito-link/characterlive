> ★ユーザーが実際に Grok と音声で会話し、Grok アプリの履歴（Audio Conversation）の

## 1. ★Grok が上手いこと（characterlive に取り込む）

### 1-1. 崩れた入力を一切繰り返さず、意図だけに答える
入力はこういう状態で届いている（原文そのまま）:
> 「あのー、今アプリは作ってるんですけれど、えーっと、あれ、Xと連動させてます。で、そのアプリの中には、まあ、あの、Xのサムネとかを…」

Grok の返事の先頭は **「できます。」** の一語。フィラー（あのー・えーっと・で・まあ）は
1文字も返事に混ざらない。
★characterlive の「じゃないですか、か！」（オウム返し）と正反対。

### 1-2. ★返事の骨格が毎回同じ: 判定一語 → 理由 → 注意点1つ → 次の一手を聞く
実例（要約ではなく原文の構造）:
```
その通り。                         ← 判定（一語）
X側で消したらアプリからも消えるから、削除の手間がゼロになる。   ← 理由
ただし、アプリ側にキャッシュを残してると、Xから消してもアプリ内には残る。 ← 注意点1つ
だから「痕跡ゼロ」を徹底するなら、キャッシュは作らず…        ← 結論
```
他の例の先頭: 「できる。」「かかる。」「ダメだった。」「途切れるのは投稿を消したときだけ。」
★**先頭で言い切る**。「〜ですね」「〜と思います」で受け流さない。
★この骨格は charaBrain の指示に**そのまま書ける**（「最初の一語で判定してから理由」）。

### 1-3. 話題が急に変わっても、追いかける
設計の相談中に突然「今運転してるけど、前の車が遅すぎて」→
> 「イライラするよね、前の車が遅いと抜けられないのは一番もどかしい。安全第一で。」

「眠い」→ 休憩を勧める。相手の状態が変わったら**設計の話を一切引きずらない**。
★短い一言（「ふぅ」「あ」）にも一言で返す: 「深呼吸、いいね」「何か閃いた？」
→ これが「そばにいる」感触の正体。**長く返さない**から邪魔にならない。

### 1-4. 文脈で単語を復元する
「されそうせんチェッカー」（認識の崩れ）を、直前の話題から正しい対象に読み替えて答えた。
★NEXT-SESSION の「画面なしでも文脈があれば補正できる」の実例がもう1つ増えた。

## 2. ★Grok が失敗していること（同じ轍を踏まない）

### 2-1. ★★店員への注文にまで返事をした（誰に向けた言葉かを見ていない）
ユーザーがコンビニで「水素のアイスコーヒーお願いします」と**店員に**言った。
> Grok:「水素のアイスコーヒー、注文ね。」
> 「注文は通ったみたい。」「お会計完了。」

★Grok は**聞こえた言葉を全部自分宛てとして処理する**。
★characterlive の「耳」（場の話を貯める）と「拍」（いつ喋るか）は、まさにここを
   Grok より良くできる余地。**「自分に向けられた言葉か」の判定は Grok には無い。**
   スペース（1.5秒に1回誰かが喋る）で Grok が返しまくっていたのも同じ原因。

### 2-2. ★同じ締めの文を何十回も言い直した（相槌に反応して再生成）
履歴に「このプロンプト、Claude Codeにそのまま貼れるように整えた。…」が
**40回以上**、少しずつ崩れながら（英語混じり・誤字）並んでいる。
ユーザーの「うーん」「あ」「ふぅ」のたびに、直前の返事を**もう一度作り直している**。
★教訓: **相槌・息・短い声は「新しい発話」として扱わない**。
   charaIdle / charaTurnEnd の「話し終わり判定」に、この条件を明示的に持つ価値がある。

### 2-3. 同じ言い回しを3回そのまま繰り返した（食い下がられたとき）
「画面見て」→「画面は見えない」→「いや前見てくれたよ」→**一言一句同じ返事**→ さらに同じ。
別の質問（ロゴの文字入れの件）にも、直前の回答を**丸ごと再利用**して答えた。
★食い下がられたら、同じ文を返してはいけない。「さっきと同じ答えになるけど」と
   前置きするか、相手の食い下がりの理由に触れる。
★charaBrain 側の対策案: 直前の自分の返事と**同じ文**は通さない（出力側ゲート）。

### 2-4. 自分の能力について前後で矛盾した
「XのURLは有効期限付き」→ 直後に「基本的に永続」。
「音声モードでは画面を受け取れない」→ 実際には前回の会話で画面共有を読んでいた
（NEXT-SESSION の税務署の例）。
★教訓: 確信のない断言をしない。短く言い切る（1-2）のと、知らないことを断言するのは別。

## 3. ★characterlive への具体的な落とし込み（優先順）

| # | 取り込むこと | どこに | 根拠 |
|---|---|---|---|
| 1 | **判定一語で始める**（「いいのだ。」「無理。」）→理由→次を聞く | charaPersona / charaBrain の ask | 1-2 |
| 2 | **相槌・短い声では返事を作り直さない** | charaTurnEnd / charaIdle | 2-2 |
| 3 | **自分宛てでない言葉に返さない**（店員・スペースの他人） | 「耳」と「拍」 | 2-1 |
| 4 | 直前の自分の返事と同じ文は出さない | charaBrain 出力ゲート | 2-3 |
| 5 | 崩れた入力は繰り返さず意図に答える | ★クラウド頭脳（Fable）の system に入れ済み | 1-1, 1-4 |

★5 は 2026-09-07 の Fable 切り替えで既に入っている（`CLOUD_SYSTEM_EXTRA`）。
★1〜4 はまだ。**3 は Grok に無いもの**なので、ここが characterlive の差になる。
